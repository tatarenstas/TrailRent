# TrailRent — сервіс прокату туристичного спорядження

## 1. Предметна область

**TrailRent** допомагає туристам орендувати спорядження для походів: намети, рюкзаки, спальники, пальники та трекінгові аксесуари. Клієнт обирає спорядження на конкретні дати, оформлює бронювання, забирає комплект у пункті видачі й повертає його після мандрівки. Система повинна зберігати склад і характеристики спорядження, не допускати видачу неготового інвентарю, фіксувати оплату та дозволяти учасникам спільноти залишати відгуки й обговорювати маршрути.

## 2. Контексти та технології персистентності

| Контекст | База | Технологія | Чому саме вона |
|---|---|---|---|
| Бронювання та клієнти | `TrailRent_BookingDB` | SQL Server + ADO.NET/Dapper | Видача і повернення — транзакційні операції зі строгими переходами станів. Збережувані процедури гарантують, що спорядження не видадуть до підтвердження та оплати. |
| Каталог спорядження | `TrailRent_CatalogDB` | SQL Server + EF Core (Code First) | Каталог містить 1:1, 1:N і M:N зв'язки. Fluent API та міграції EF Core природно описують цю модель і дозволяють версіонувати схему. |
| Відгуки та спільнота | `TrailRent_CommunityDB` | MongoDB | Відгук читається разом з автором і відповідями, тому це один документ. Обговорення маршруту може необмежено зростати, отже повідомлення в ньому посилаються на дискусію окремо. |

Детальна модель, агрегати та правила дублювання описані в [docs/architecture.md](docs/architecture.md) і [docs/aggregates.md](docs/aggregates.md).

## 3. Розгортання з нуля

### Контекст 1 — бронювання

У SQL Server Management Studio виконайте в зазначеному порядку:

1. `db/p1/schema.sql`
2. `db/p1/procedures.sql`
3. `db/p1/seed.sql`

`schema.sql` призначений для локальної розробки: він видаляє існуючу `TrailRent_BookingDB`, тому не запускайте його на базі з важливими даними.

### Контекст 2 — каталог

1. Виконайте `db/p2/schema.sql`.
2. Виконайте `db/p2/seed.sql`.

У наступній лабораторній цю схему буде перенесено в EF Core Code First; принцип та приклад команд є в [docs/migrations.md](docs/migrations.md).

### Контекст 3 — спільнота

У `mongosh` з кореня репозиторію:

```bash
mongosh "mongodb://localhost:27017" --file db/p3/collections.js
mongosh "mongodb://localhost:27017" --file db/p3/seed.js
```

Скрипт `collections.js` створює колекції та індекси, а `seed.js` використовує upsert, тому його можна запускати повторно без дублікатів. Перевірочні запити зібрані в [docs/checks.md](docs/checks.md).
